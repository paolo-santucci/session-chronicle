# Diagnostics

## Overview

The operator-facing health surface of a Chronicle project: one read-only command that answers whether the plugin is installed and loaded, what the store contains, whether retrieval will still surface topic notes, and whether anything is stuck, plus two static linters that enforce definition and documentation contracts (`skill/session-chronicle/scripts/chronicle-doctor.py`, `scripts/lint-agents.py`). Diagnosis never implies repair — no command in this domain writes to the project or fixes what it reports.

## Current behaviour

- **Reports installation state, not activity.** The doctor reads the module `package.json` version, the presence of the `.session-chronicle-install.json` marker, and whether an OpenCode plugin entry exists, preferring the `.opencode/plugins/session-chronicle.ts` shim over the portable `.opencode/plugins/session-chronicle/index.ts` entry, and records which of the two was found (`skill/session-chronicle/scripts/chronicle-doctor.py:61-80`).
- **Censuses the store by kind.** Every `sessions/*.md` and `topics/*.md` note is bucketed by `record-kind`, then `note-kind`, falling back to `legacy`; notes that cannot be read as UTF-8 or whose frontmatter fails are counted as `unreadable` rather than dropped (`skill/session-chronicle/scripts/chronicle-doctor.py:43-58`, `176-182`).
- **Reports the retrieval window instead of running retrieval.** It builds the same candidate corpus (sessions + topics, newest mtime first), asks the shared selector for the eligible partition, splits it into topics and sessions, and reports the scan cap, the topic count, the eligible-session count and how many topics fall outside the window (`skill/session-chronicle/scripts/chronicle-doctor.py:83-106`). Topics are reported as taking the first scan slots; sessions fill the remainder.
- **Reports staleness.** The newest `sessions/*.md` file is named with its age in days (`skill/session-chronicle/scripts/chronicle-doctor.py:184-191`).
- **Reports stuck work.** Sealed `.drafts/pending/*.jsonl` batches are counted as problems; `.drafts/*.draft.jsonl` files are split into those with content (listed with byte sizes) and empty ones (`skill/session-chronicle/scripts/chronicle-doctor.py:109-120`).
- **Reports structural audit findings.** It loads `skill/session-chronicle/scripts/memory-audit.py` beside itself and runs its audit in quality mode, reporting the finding count and the sorted set of finding codes; if the module cannot be loaded or the call raises, audit is reported as unavailable with no finding count (`skill/session-chronicle/scripts/chronicle-doctor.py:123-148`).
- **Classifies the project into one of four verdicts.** Problem and warning texts are accumulated, then `healthy` / `degraded` / `not loaded` / `invalid docs-root` is selected together with a numeric code (`skill/session-chronicle/scripts/chronicle-doctor.py:204-234`).
- **Renders either human text or JSON.** Text output leads with docs-root provenance, install line, counts, retrieval window, last note, drafts and audit, then PROBLEM/warn/note lines and `verdict`; JSON output is the full report dict, sorted and indented (`skill/session-chronicle/scripts/chronicle-doctor.py:237-283`, `294-298`).
- **Suppresses the exit code unless asked.** Without `--strict` the command exits 0 whatever the verdict; with `--strict` the verdict's code becomes the process exit code (`skill/session-chronicle/scripts/chronicle-doctor.py:299-301`), which the documentation states as a contract (`README.md:157-164`).
- **Is admitted read-only.** The command declares no writes, no network and stdlib-only operation so it cannot fail on a project that would otherwise work (`skill/session-chronicle/scripts/chronicle-doctor.py:11-19`); no flag offers a repair.
- **Warns when capture and reads disagree.** Notes found outside the resolved docs-root produce a warning that capture and guards are writing somewhere the reader is not looking (`skill/session-chronicle/scripts/chronicle-doctor.py:167-174`).
- **Lints shipped agent definitions.** `lint-agents.py` reads every `skill/<dir>/SKILL.md` and `command/*.md`, requiring YAML frontmatter that parses with unique keys, a non-empty `description`, boolean `user-invocable`, string `allowed-tools`/`license`/`compatibility`, and a string-to-string `metadata` map (`scripts/lint-agents.py:68-104`, `141-158`).
- **Lints skill identity.** A skill's `name` must match `[a-z0-9]+(-[a-z0-9]+)*`, be at most 64 characters, and equal its directory name; each `command/*.md` stem must name an existing skill, and a user-invocable skill with no command shim produces a warning (`scripts/lint-agents.py:125-138`, `148-151`).
- **Lints shell usage in fenced bash blocks.** A `grep` invocation in a ```bash block — including in `if`/`while`/`until`/`else`/`then`/`do`/`$()`/subshell/`&&` positions — is an error directing the author to `rg`; quoted literals, comments, `grep-helper`, `var=grep` and prose are not flagged (`scripts/lint-agents.py:107-114`; `tests/test_lint_agents.py:153-197`).
- **Restricts its own scope.** Only non-dot entries of `skill/` and `command/` at the repo root are validated, so installed copies under `.opencode/skills/`, `skills/`, `.opencode/command/`, `agents/` and `rosters/` are never inspected (`scripts/lint-agents.py:117-122`; `tests/test_lint_agents.py:50-54`).
- **Fails actionably when its dependency is absent.** Without PyYAML the linter prints the exact `pip install -r scripts/requirements-lint.txt` remedy and exits 1 (`scripts/lint-agents.py:167-170`; `tests/test_lint_agents.py:213-218`).
- **Asserts documentation against the code.** A contract suite pins the four reader-facing documents to shipped behaviour: README provenance-line format, tunable names and single budget authority, dedup wording, and the doctor's exit-code semantics; the shared `SKILL.md` reply shape `{text, slugs}` and `kind:stem` references; the capability matrix's retrieval row verbatim with negations refused; and the verification record against the performance report that produced its figures (`tests/test_docs_contracts.py:17-26`, `33-181`).

## Public contracts

- **CLI**: `python3 chronicle-doctor.py [--project PATH] [--json] [--no-audit] [--strict]` (`skill/session-chronicle/scripts/chronicle-doctor.py:286-292`). Documented invocation targets the installed copy (`README.md:172-174`).
- **Exit codes**: 0 healthy, 1 degraded, 2 not loaded, 3 invalid docs-root — and only under `--strict` (`skill/session-chronicle/scripts/chronicle-doctor.py:15-17`, `299-301`; `README.md:161-164`). Tests assert 0 without `--strict` even when degraded and 1/2/3 with it (`tests/test_chronicle_doctor.py:92-94`, `104-121`, `144-152`).
- **JSON report shape**: `project`, `docs_root`, `declared_by`, `exists`, `problems[]`, `warnings[]`, `notes[]`, `install{module_version,marker,portable_entry,loaded,loaded_by}`, `sessions{by_kind,unreadable,total}`, `topics{by_kind,unreadable,legacy,total}`, `last_capture{note,age_days}|null`, `retrieval{cap,eligible_sessions,topics,topics_out_of_window,note}`, `drafts{pending_batches,drafts_with_content[],empty_drafts}`, `audit{available,findings,by_code}` (on success), `verdict`, `code` (`skill/session-chronicle/scripts/chronicle-doctor.py:151-201`, `100-106`, `145-146`).
- **Callable surface exercised by tests**: `retrieval_window(project, base)`, `inspect(project, with_audit=True)`, `verdicts(report)`, `render(report)`; `retrieval_window` must call the shared `select_candidates` exactly once and must not reference retrieval's own partition names (`tests/test_chronicle_doctor.py:154-195`).
- **Message vocabulary relied on by tests and docs**: `captures nothing`, `no memory captured yet`, `no semantic summaries`, `invalid docs-root`, `DEGRADED` in rendered output (`tests/test_chronicle_doctor.py:102`, `109`, `121`, `136`, `152`).
- **Linter CLI**: `python3 scripts/lint-agents.py [--repo PATH] [-q|--quiet]`, defaulting to the checkout containing the script (`scripts/lint-agents.py:162-166`). Exit 0 when clean or warnings-only, 1 on any error or missing PyYAML (`scripts/lint-agents.py:4`, `183`).
- **Linter output shape**: warnings as `  ~ <path>: <message>` on stdout, errors as `  ! <path>: <message>` on stderr, then `\n<c> commands, <s> skills — <e> error(s), <w> warning(s)`; `-q` hides warning text but keeps the count (`scripts/lint-agents.py:177-183`; `tests/test_lint_agents.py:115-124`). Diagnostics are expected to be clean — no traceback, and I/O errors surface the OS message (`tests/test_lint_agents.py:37`, `203-211`).
- **Dependency pin**: `scripts/requirements-lint.txt` pins `PyYAML==6.0.3`.
- **Read-only promise**: no invocation path in this domain mutates the project, the store or configuration (`skill/session-chronicle/scripts/chronicle-doctor.py:11-13`; `scripts/lint-agents.py` reads only).

## Enumerated providers / limits

- **Verdicts** (closed set, `skill/session-chronicle/scripts/chronicle-doctor.py:229-234`): `healthy`, `degraded`, `not loaded`, `invalid docs-root` — documented as having no fourth exit code (`README.md:164`).
- **Verdict precedence** (`skill/session-chronicle/scripts/chronicle-doctor.py:229-234`): any problem with the plugin unloaded or module version missing → `not loaded`/2; any other problem → `degraded`/1; only warnings → `degraded`/1; nothing → `healthy`/0.
- **Flags** (closed set, `skill/session-chronicle/scripts/chronicle-doctor.py:288-291`): `--project` (default cwd), `--json`, `--no-audit`, `--strict`.
- **Kind buckets** (`skill/session-chronicle/scripts/chronicle-doctor.py:54-57`): `record-kind` → `note-kind` → `legacy`.
- **Audit mode invoked by the doctor** (`skill/session-chronicle/scripts/chronicle-doctor.py:134-139`): `quality=True`, `threshold=2`, `days=90`; `orphans`, `dups`, `dangling`, `stale`, `materialization_candidates` all false — i.e. quality-only.
- **Retrieval scan cap**: `MEMORY_INJECT_MAX_SCAN`, default `60`, read from the environment at check time (`skill/session-chronicle/scripts/chronicle-doctor.py:99`).
- **Skill name limit**: 1–64 characters, lowercase alphanumerics with single separating hyphens (`scripts/lint-agents.py:20`, `131-132`).
- **Diagnostic truncation**: offending `grep` lines are echoed to 70 characters (`scripts/lint-agents.py:114`).
- **Test-side timeouts**: doctor subprocess invocations bound at 20 s (`tests/test_chronicle_doctor.py:89`, `150`).

## Cross-domain dependencies

- **docs-root resolution** — `resolve` and `detect_orphan` from `skill/session-chronicle/scripts/_docsroot.py` decide the root, its declaring file and the orphan warning (`skill/session-chronicle/scripts/chronicle-doctor.py:31`, `155-174`); documented as the shared boundary-validating resolver (`README.md:98`).
- **retrieval candidate partition** — `select_candidates` from `skill/session-chronicle/scripts/_session_notes.py` is the single authority for eligibility; duplicating that partition in the doctor is treated as a defect (`skill/session-chronicle/scripts/chronicle-doctor.py:32`, `96`; `tests/test_chronicle_doctor.py:17-28`, `183-195`).
- **note frontmatter parsing** — `read_frontmatter` and `parse_fields` from `skill/session-chronicle/scripts/_topic_graph.py` (`skill/session-chronicle/scripts/chronicle-doctor.py:33`, `50`).
- **memory audit / `memory_audit` tool** — `skill/session-chronicle/scripts/memory-audit.py` is loaded dynamically and its `audit()` called in quality mode (`skill/session-chronicle/scripts/chronicle-doctor.py:123-148`); documented as the tool that exposes structural findings for semantic review (`README.md:210`).
- **capture and drafts** — pending batches, live drafts and empty drafts are read from `<docs-root>/.drafts/` (`skill/session-chronicle/scripts/chronicle-doctor.py:109-120`), the store layout documented in `README.md:94-95`.
- **plugin installation and packaging** — module `package.json`, install marker and `.opencode/plugins/` entries are the installation signals (`skill/session-chronicle/scripts/chronicle-doctor.py:61-80`); the installer is a separate deployment owner (`README.md:69-73`).
- **shipped skill/command definitions** — `skill/<id>/SKILL.md` and `command/*.md` are the artifacts `lint-agents.py` validates (`scripts/lint-agents.py:141-158`).
- **documentation artifacts** — `README.md`, `skill/session-chronicle/SKILL.md`, `docs/capability-matrix.md`, `docs/verification.md` and `docs/reports/sp-20261116-retrieval-perf-baseline.md` are the documents the contract suite holds to the code (`tests/test_docs_contracts.py:17-22`).

## Gaps

- **`skill/session-chronicle/scripts/_docsroot.py` behaviour is unverified here.** `resolve()` and `detect_orphan()` live outside the assigned paths; the entire docs-root verdict, the `declared_by` string and the orphan warning depend on their escape rules (`skill/session-chronicle/scripts/chronicle-doctor.py:155-174`). Whether a valid-but-wrong root is reported as a problem or only as an orphan warning cannot be settled from this slice.
- **`skill/session-chronicle/scripts/memory-audit.py`'s `audit()` contract is unverified.** Only the `Args` shape the doctor constructs is in evidence (`skill/session-chronicle/scripts/chronicle-doctor.py:134-146`); what `report["quality"]` entries look like, and whether `threshold`/`days` mean what their names suggest, is outside scope.
- **Audit failure is silent.** Any exception while loading or calling the audit is swallowed into `{"available": False, "findings": None}` (`skill/session-chronicle/scripts/chronicle-doctor.py:131-132`, `147-148`), rendered as `audit unavailable` (`skill/session-chronicle/scripts/chronicle-doctor.py:270`). Is a broken audit a non-event by design, or should it degrade the verdict? Today it affects neither verdict nor exit code.
- **`installation.loaded` proves a file exists, not that it loads.** Presence of the shim or the portable entry sets `loaded=True` without inspecting content or the module it re-exports (`skill/session-chronicle/scripts/chronicle-doctor.py:73-79`), and the shim wins when both exist. A stub or broken shim reports as loaded.
- **The rendered portable version is hardcoded.** `render()` prints `portable 0.2.1` whenever a portable entry exists and no module version was read (`skill/session-chronicle/scripts/chronicle-doctor.py:248`), so the string cannot track the package version and will misreport after a bump.
- **The retrieval window is a model, not a measurement.** `topics_out_of_window` is computed as `max(0, len(topics) - cap)` while sessions are counted without any cap (`skill/session-chronicle/scripts/chronicle-doctor.py:99-105`). Whether this mirrors the scan consumption of the `retrieve-inject.py` file the code comment names (`skill/session-chronicle/scripts/chronicle-doctor.py:98`) is not verified — that script is outside the assigned paths.
- **Requirement identifiers cited without text.** `test_chronicle_doctor.py` invokes FR-37, EC-37 and OQ-30 to justify the shared-partition rule (`tests/test_chronicle_doctor.py:17-19`, `191-192`), but no requirement text is in scope. The structural assertion is enforced; whether it is a ratified requirement or an open question needs confirmation.
- **Linter coverage is narrower than the shipped surface.** Only `skill/` and `command/` are scanned (`scripts/lint-agents.py:142-147`); the neutral workflow sources under `skills/<skill-id>/` and adapter definitions are unlinted (`README.md:31-34`). Intentional boundary or oversight?
- **The missing-shim warning may contradict the stated policy.** Every user-invocable skill without a `command/` shim warns (`scripts/lint-agents.py:137-138`), while the documentation states redundant commands are not required because native skill invocation supplies entrypoints (`README.md:66-67`). Warning noise, or a deliberate nudge?
- **The documentation contract suite pins build-produced figures.** `test_docs_contracts.py` asserts specific test counts and verbatim latency figures (`tests/test_docs_contracts.py:10-11`, `126-144`, `156-174`). Treating those as canon would put a verification snapshot into the spec; whether the suite is a release gate to update per build or a fixed contract is a human call.
